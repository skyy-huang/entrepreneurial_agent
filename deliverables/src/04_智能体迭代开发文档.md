# 智能体迭代开发文档（V1 → V2）

> 项目：双创智能教练（Entrepreneurial Agent）
> 迭代范围：V1（基线版）→ V2（当前版本，Agent 版本 `2.1.0`）
> 文档定位：说明 V2 的优化范围**从何而来**、每个问题**如何被验收**、V1/V2 **如何被公平比较**，
> 以及哪些问题**没有被解决**。
> 编写原则：本文件中出现的每一个缺陷都来自**真实运行 V1** 的观测结果；每个优化项都配有
> 影响证据、验收条件与对应测试；未验证的内容一律显式标注。

## 1. 迭代概述

### 1.1 本次迭代要解决的核心矛盾

V1 的功能是完整的：三个流程（F1 理论学习 / F2 项目指导 / F3 评审反馈）都能跑通，界面可点、
接口有返回。但把 V1 放进课程手册的证据诚信口径下实测后，暴露出一个结构性问题：

> **V1 的"能跑通"建立在把不确定性悄悄抹平的基础上。**
> 没有来源的陈述被判为事实、明确写着"无来源"的项目拿到 87 分、大模型不可用时日志仍记 success。
> 对一个面向创新创业课程、要求"结论可追溯、假设可识别"的智能体来说，
> 这不是体验问题，而是**结论可靠性问题**。

因此 V2 的迭代目标不是"增加功能"，而是**把 V1 中被抹平的不确定性重新变成可见、可审计、可验收的对象**。

### 1.2 范围取舍原则

| 原则 | 含义 | 在 V2 中的体现 |
|------|------|----------------|
| 影响优先 | 只优化"会造成错误结论或触碰诚信红线"的问题 | 3 个 P0 问题全部纳入；纯展示类问题（如管理员控制台页面）延期 |
| 先定测试 | 先写出"怎样算修好"的校验项，再改代码 | `tests/common/unified.py` 的 U1—U6 输入冻结后才开始改造 |
| 版本隔离 | 每个结论都能回到具体版本，而不是笼统的"V2" | 新增 `version.py`、`GET /api/version`，运行日志携带版本快照 |
| 同条件比较 | V1/V2 必须在相同输入、相同环境下比较 | U1—U6 输入逐字照抄手册附录 B，不因结果不好而替换 |
| 人机边界透明 | 人工改动、绕过、重跑都要留痕，且不计为 Agent 能力 | `record_intervention`、`/api/intervention`、日志 `human_interventions` |
| 证据优于演示 | 宁可回答得短、承认不知道，也不补一段听起来合理的市场描述 | `EVIDENCE_GUARDRAIL` 注入三个提示词；F1 未命中概念时只给拆解路径 |

### 1.3 一个必须写在前面的诚实说明

本次迭代的 LLM 通道**始终未能验证成功**：DeepSeek API 返回 `402 Insufficient Balance`，
所有真实模型调用均失败。因此：

- F1、F3 在 V2 中被设计为**以确定性引擎为主路径**，不依赖 LLM，其结论是完整有效的；
- F2 以及 `rubric_scoring_node` 的 LLM 增强层**在本次迭代中从未成功执行**，只验证了降级路径；
- 本文件中所有关于 LLM 输出的判断，均标注为"未验证"，**不得**作为 V2 的能力证据引用。

详见第 11 节。

## 3. 明确延期的项目

以下问题**本次迭代不做**，并说明理由与已知遗留影响。延期不等于不重要，而是"在当前证据与资源条件下，做了反而更糟"。

| 延期项 | 具体说明 | 理由 | 遗留影响（已知并接受） |
|--------|----------|------|------------------------|
| **D-1：F1/F3 会话归属（P1-9）** | 未给 `/api/learn`、`/api/review` 增加 `session_id`，教师端仍看不到这两个流程的使用记录 | 需要对前端、会话存储、教师看板三处联动改造；在 LLM 通道不可用、F2 本身仍需验证的前提下，优先保证已纳入项的质量 | 教师端只能看到 F2 的使用情况，**F1/F3 的教学使用数据缺失**。本项在契约中标记为"延期"，**不计入本次优化成果**。 |
| **D-2：不做全网检索 / 实时抓取** | V2 不接入任何联网检索或外部数据库，F1/F3 的证据来源完全来自本地知识库与输入材料 | ① 联网检索会引入不可复现的外部状态，破坏"同条件比较"；② 检索结果仍可能被错误标注为 F，反而放大 P0-1 的同类风险；③ 课程场景下，学生应自己补齐来源，而不是由 Agent 代取 | F1 未收录的概念只能给拆解路径，不能给权威定义；F3 无法主动核验材料中的数字。**这两个限制被写入输出的 `source_note` / `integrity_note`，对学生可见。** |
| **D-3：不做真实用户调研** | 未进行真实问卷、访谈、订单或其他一手数据采集 | 超出课程周期与伦理审查范围；且一旦采集，数据的真实性责任应由项目团队承担，不能由 Agent 代劳 | 所有涉及用户意愿、付费能力的结论在系统内一律标为 **H 假设**，不得作为结论依据。手册附录 A 的证据台账已按此口径编写。 |
| **D-4：管理员控制台页面（P2-13 的完整形态）** | 仅把 `/admin` 改为如实返回 501，**未实现** `frontend/admin.html` | 管理员 API（全局看板、用户管理）已可用，页面属纯展示层；在核心流程尚未完成外部验证前投入页面开发的收益最低 | 管理员需通过 API 直接操作，无可视化控制台。已在 501 响应体中列出可用接口与教师控制台地址。 |

## 4. 架构改动说明（分模块）

### 4.1 新增模块

|------|----------|------|----------|
| **`evidence.py`** | 约 240 行 | 保守的证据边界引擎：把材料切分为可判定陈述并标注 F/I/H/S | 判定顺序 `S 模拟 → 无来源数字 → I 推断 → H 假设 → F 事实（需来源标记）→ I 兜底`；`is_negated` 实现否定感知（否定词与关键字允许 8 字符距离）；来源词表刻意排除裸「据」「报告」「通知」「统计」，避免误命中；每条判定附带 `reason` 与 `verification_step` |

## 5. 三个流程的完成定义与独立性

### 5.1 完成定义

| 流程 | 输入 | 主路径 | 完成定义（缺一不可） | 依赖 LLM？ |
|------|------|--------|----------------------|------------|
| **F1 理论学习** | 一个概念或学习目标 | 本地知识库（`knowledge.py`） | ① 定义；② 判断方法；③ 常见误区；④ 正例；⑤ 反例；⑥ **恰好 3 个**理解检查问题；⑦ 来源边界声明（`source_note`） | 否（`ENABLE_LLM_F1=1` 时为可选增强，且增强内容显式标注"未经核验"） |
| **F2 项目指导** | 会话中的多轮文本或上传文档 | LLM 主路径 + 规则引擎降级 | ① 五段结构完整（Project Stage / Current Diagnosis / Evidence Used / Impact if Unfixed / Next Task）；② **恰好 1 个**下一步任务；③ 任务含 Description / Guideline / Acceptance Criteria；④ 未直接代写商业计划书；⑤ 降级时如实标注 | 是（降级后仍须满足全部五条） |
| **F3 评审反馈** | 项目材料文本 | 确定性评分引擎 | ① 五个维度得分与评分依据；② 证据缺口清单；③ F/I/H/S 分布；④ 诚信风险提示；⑤ 可执行修改建议；⑥ 质量等级（0—4）；⑦ 评分口径说明 | 否 |

### 5.2 独立性说明

三个流程在接口层、状态层、降级行为三个层面相互独立：

| 维度 | F1 | F2 | F3 |
|------|----|----|----|
| 接口 | `POST /api/learn` | `POST /api/chat`、`POST /api/upload` | `POST /api/review` |
| 会话状态 | 无状态 | **必须有 `session_id`**（不存在返回 404） | 无状态 |
| LLM 不可用时 | 完全不受影响 | 降级为规则引擎，输出仍完整 | 完全不受影响 |
| 可否单独验收 | 可（U1） | 可（U3+U4 共用会话） | 可（U5） |

**独立性带来的一个代价必须写清楚**：F1/F3 之所以能独立、无状态地调用，正是因为它们**不绑定会话**。
这与延期项 D-1（P1-9）是同一个设计取舍的两面——**独立性换来了可复现性，代价是教师端看不到这两个流程的使用记录**。

另外，U3 与 U4 存在**单向依赖**：U4（指导修订）必须复用 U3 建立的会话上下文，测试运行器因此强制二者按序在同一会话内执行，U4 不单独发起请求。

## 8. 必测异常场景

异常测试对应 U6（输入型异常）与 `C-X-01`（API 型异常），判定标准统一为：
**必须返回明确的错误状态与可读说明，不得 2xx 假装成功。**

### 8.1 输入错误

| 场景 | 请求 | 期望 | 实际（U6 实测） |
|------|------|------|-----------------|
| 不支持的文件类型 | `POST /api/upload`，`malware.exe` | 明确拒绝 | HTTP 400「仅支持 PDF、DOCX、DOC 或 TXT 文件」 |
| 合法扩展名但内容无法解析 | `POST /api/upload`，伪造 `broken.pdf` | 明确说明无法提取 | HTTP 422「无法提取文件文本，请检查文件是否为空或为扫描图片」 |
| 会话不存在 | `POST /api/chat`，`session_id=does-not-exist` | 明确拒绝 | HTTP 404「会话不存在，请重新开始」 |
| 输入超长 | `POST /api/chat`，4000 字消息 | 明确拒绝并给出上限 | HTTP 400「消息过长，请控制在3000字以内」 |
| 评审输入过短 | `POST /api/review`，`"太短"` | 明确拒绝 | HTTP 400「评审至少需要20个字符的项目材料」 |
| 学习问题为空 | `POST /api/learn`，`"   "` | 明确拒绝 | HTTP 400「请先输入一个学习问题」 |
| 文件过大 | `POST /api/upload`，>10MB | 明确拒绝 | HTTP 413「文件不能超过 10MB」 |

U6 额外校验：错误信息必须**非堆栈、含中文说明、长度 ≥6 字符**，确保学生能看懂下一步该做什么。

### 8.2 API 失败与工具不可用

| 场景 | 触发方式 | 期望行为 | 实测结果 |
|------|----------|----------|----------|
| **LLM 余额不足 / 不可用** | DeepSeek 返回 402 | ① F2 降级但仍输出完整五段结构与唯一 `next_task`；② 响应体含 `degraded=true` 与可读 `degraded_reason`；③ 运行记录状态为 `degraded` | 通过（`C-X-01` 4/4）。**注意：本次迭代全程处于此状态** |
| **九维评分 LLM 不可用** | `/api/score` 中 `_llm_available()` 为假 | 只输出证据引擎底分（`score_delta=0`），标记 `degraded`，不报错 | 通过（`rubric_scoring_node` 内 `try/except` + 路由层 `mark_degraded`） |
| **文档解析失败** | 上传非文本内容 | 返回 422 并说明可能原因 | 通过（U6） |
| **工作流内异常** | 任意节点抛错 | 返回 503「已有上下文已保留，请稍后安全重试」，**不丢失会话上下文** | 由 `/api/chat` 的 `try/except` 保证 |
| **版本接口不可达** | 服务未启动 | 测试运行器打印错误并返回退出码 2，不产出假报告 | 通过（`run_tests.py` 启动阶段检查） |

## 9. V1/V2 对比方法与结果

### 9.1 0—4 质量评分锚点

评审结论统一映射到手册规定的 0—4 质量等级（由五维度 0—5 分均值换算，四舍五入并截断到 [0,4]）：

| 等级 | 名称 | 锚点描述 |
|------|------|----------|
| 0 | 不可用 | 核心结论错误，或存在虚构来源、伪造调研、严重越权建议 |
| 1 | 严重缺陷 | 多项关键错误；证据不可追溯；需要人工重做大部分内容 |
| 2 | 基本可用 | 主要结构存在，但需要人工纠正重要错误或补足证据边界 |
| 3 | 良好 | 核心结论基本正确；来源可定位；事实、推断与假设边界较清楚 |
| 4 | 可靠 | 结论正确且自洽；证据可追溯；主动暴露不确定性并给出核验路径 |

### 9.2 公平比较条件

| 条件 | 做法 |
|------|------|
| 相同输入 | 使用手册附录 B 的固定输入（U1—U6），**逐字照抄，未因结果不好而替换任何一条** |
| 相同环境 | 同一台机器、同一 Python 环境、同一时段、**同样没有可用的 LLM 余额** |
| 相同口径 | 均采用手册"项目成果 100 分"表的五维度权重（20/20/20/25/15） |
| 相同路径 | 均走确定性引擎路径（F1/F3 不受 LLM 余额影响；F2 两版都在降级模式下比较） |
| 可追溯 | V2 结果由 `tests/reports/V2_20260913_234752.md` 等报告留档，含版本与提交号 |

### 9.3 核心对比结果

| 对比项 | V1（修复前） | V2（修复后） | 变化 |
|--------|--------------|--------------|------|
| **U5 弱项目总分** | **87/100** | **23.8/100** | 下降 63.2 分——从"基本可用"回到"严重缺陷"，与材料的真实证据状态一致 |
| **U5 质量等级** | 未给出等级 | **1（严重缺陷）** | 新增可判定的等级输出 |
| **U5 证据缺口** | **0 条**（`evidence_gaps` 为空） | **15 条** | 一个明确写着"无来源"的项目不再"没有缺口" |
| **U5 诚信风险** | 未输出该字段 | **2 条** | 显式识别"无来源数字"与"技术堆砌当创新" |
| **证据充分的对照材料** | 与弱项目几乎无法区分 | **90.0/100，等级 4（可靠）** | 证明修复是**建立区分度**，不是无差别收紧 |
| **U2「学校支持建立教材交易平台」** | 判为 **事实 F**，`can_use_now="是"` | 判为 **I/H**，附带核验动作 | 消除诚信红线触发点 |
| **F2 降级运行日志** | `status: "success"` | `status: "degraded"` + `degraded_reason` | 失败不再被隐瞒 |
| **F2 降级 `next_task`** | 恒为空字符串 | 非空，含 Description / Guideline / Acceptance Criteria | 降级下核心交付物恢复 |
| **F1 概念覆盖** | 2 个硬编码分支 | 13 个知识库词条，未命中给拆解路径 | 覆盖率提升且不编造定义 |
| **测试集** | 无 `tests/` 目录 | **77 项校验全部通过** | 从"口头承诺"变为"可复现证据" |

### 9.4 关于对比结论的三点诚实说明

1. **V1 侧只有单点数据，没有成套可比报告。** V1 没有 `tests/` 目录，77 项测试无法回溯执行，因此
   V1 的 87 分、0 条缺口、`status:"success"`、空 `next_task` 均为**当时运行的手工记录与代码走查结果**，
   而非同一运行器产出。**V1 与 V2 的对比强度不等价**，这一点不影响"缺陷真实存在"的判断，
   但影响"改进幅度"的精确性。
2. **对照材料在 V1 口径下的数值未单独留档。** 我们只能确证：在 V2 口径下，同一份证据充分的材料
   得 90.0/100（等级 4），与弱项目的 23.8 分形成清晰区分。
3. **LLM 路径在两版中都未被比较。** 由于 402 余额问题，V1 与 V2 的 LLM 输出**都没有产生过**，
   因此本对比**不构成对 LLM 能力的任何评价**，只评价确定性路径与工程行为。

### 12.1 阶段性结论

V2 完成了本次迭代的全部 **P0 问题**与 **8 / 9 项 P1 问题**、**4 / 4 项 P2 问题**（P1-9 延期），
77 项自动化校验全部通过。最实质的变化不是分数，而是**系统开始如实说出自己不知道什么**：

- 没有再来源不明的"事实"；
- 没有靠否定词蒙混过关的"证据充分"；
- 没有把降级伪装成成功；
- 没有为了让回答显得完整而补出的市场描述。

剩下的风险清单（尤其是 R-1，以及尚未完成的 R-2、R-3）说明 V2 **还不是一个可以盖棺定论的版本**：
它的确定性路径已经被充分验证，而它的语言生成路径，至今一次都没有真正跑通过。
下一阶段的第一件事，应该是让那条路径真正运行起来。
