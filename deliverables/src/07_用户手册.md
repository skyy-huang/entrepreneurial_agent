# 双创智能教练（Agent V2）用户手册

> 适用版本：Agent V2（`agent_version = 2.1.0`，`agent_stage = V2`）
> 适用对象：使用本系统开展创新创业课程学习的学生、任课教师与系统管理员
> 最后更新：2026-09

---

## 一、系统简介

### 1.1 它是什么

双创智能教练（工作台名称「原点」）是一个基于 FastAPI 的创新创业项目诊断智能体。它把学生的自然语言描述提取为结构化商业要素节点与超边，用 H1—H15 逻辑审计规则找出项目最危险的逻辑缺口，再以苏格拉底提问法给出「下一步就能做完」的行动任务。

系统提供三个可独立验收的工作流程：

| 流程 | 名称 | 入口接口 | 一句话说明 |
|------|------|----------|------------|
| F1 | 理论学习 | `POST /api/learn` | 解释创业概念，给出正反例、判断方法与 3 个理解检查问题 |
| F2 | 项目指导 | `POST /api/chat`（文件走 `POST /api/upload`） | 围绕用户、场景、问题、替代方案与关键证据逐轮追问 |
| F3 | 评审反馈 | `POST /api/review` | 按五维量规输出评分、证据缺口与可执行修改建议 |

围绕这三个流程，系统另提供四个支撑能力：

| 能力 | 接口 | 说明 |
|------|------|------|
| 证据标注 | `POST /api/evidence/classify` | 把材料拆成 F/I/H/S 四类并给出核验动作 |
| 竞赛评分 | `POST /api/score` | R1—R9 逐项评分（证据引擎底分 + 大模型可选加分） |
| 人工干预登记 | `POST /api/intervention` | 记录补充、修改、确认、绕过、重跑、纠错 |
| 运行日志 | `GET /api/runs`、`GET /api/runs/{run_id}` | 按运行编号回溯每一次调用的状态与耗时 |

版本快照由 `GET /api/version` 提供，返回 Agent 版本、提示词版本、知识库版本、模型名与 git 提交号。

### 1.2 它不会做什么（能力边界）

这一节是使用本系统的前提，请务必先读：

- **不代写商业计划书。** F2 只做逐轮追问与定点修订，不会一次性输出完整计划书，不会替你把项目「写完」。
- **不编造引用与来源。** F1 主路径是本地知识库，每条词条显式声明来源状态；未收录的概念只给拆解路径，不给可能不准确的定义。F3 的来源标记只代表文本中出现了「来源/出处/机构名」等线索，**不构成对内容真实性的认定**。
- **不把无来源的数字当作事实。** 材料中有具体数字但没有可定位来源时，一律标为假设 H，并提示补充机构、标题、年份与链接。
- **不把模拟材料当市场证据。** 由教师情境、案例包或 Agent 推演产生的内容标为模拟 S，只能用于生成待验证假设。
- **不替代人工判断。** 自动标注只是初筛，最终责任由项目成员承担。
- **不做外部检索。** 系统不联网核实来源，也不声称核实过。

### 1.3 降级行为是特性，不是故障

当大模型 API 不可用（未配置 Key、余额不足、网络超时、服务异常）时：

- **F1、F3 仍可完整运行**：主路径是本地确定性引擎，不依赖大模型，输出结构与正常情况完全一致。
- **F2 降级为本地规则引擎**：保留会话上下文，仍返回完整结构的回复与唯一的下一步任务，但在响应中如实给出：

```json
{ "degraded": true, "degraded_reason": "LLM 调用失败（AuthenticationError）" }
```

同时该次运行记录的状态会从 `success` 自动降级为 `degraded`，审计者可清楚区分「正常成功」与「本地兜底成功」。系统**不会**把降级伪装成外部资料检索成功。

F1 的可选大模型增强（`ENABLE_LLM_F1=1`）仅在未命中知识库时触发，补充内容一律标注「未经核验，不得直接写入正式材料」。

## 二、环境要求与安装步骤

### 2.1 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows / Linux / macOS（本项目开发环境为 Windows 11） |
| Python | 3.10 及以上，推荐 3.11 或 3.12（开发环境为 3.12） |
| 依赖管理 | pip（`requirements.txt` 已列出全部依赖） |
| 网络 | 仅在使用大模型功能时需要访问 `https://api.deepseek.com` |
| 浏览器 | Chrome / Edge 等现代浏览器（前端使用 `fetch`、`sessionStorage`） |

### 2.2 安装步骤

**第 1 步：进入项目目录并创建虚拟环境（推荐）**

```bash
cd d:/entrepreneurial_agent
python -m venv .venv
source .venv/Scripts/activate     # Windows (Git Bash)
# .venv\Scripts\activate.bat      # Windows (CMD)
# source .venv/bin/activate       # Linux / macOS
```

**第 2 步：安装依赖**

```bash
pip install -r requirements.txt
```

依赖清单：langgraph、langchain、langchain-openai、fastapi、uvicorn[standard]、python-dotenv、pydantic、httpx、PyPDF2、python-docx、python-multipart、networkx。

> `python-multipart` 是文件上传接口的必需依赖，缺失会导致 `/api/upload` 无法工作。

**第 3 步：配置环境变量**

```bash
cp .env.example .env
# Windows CMD 可用：copy .env.example .env
```

### 2.3 `.env` 配置项说明

| 变量 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `DEEPSEEK_API_KEY` | 否 | 空 | 大模型 API Key。**不配置时 F1/F3 仍可完整运行，F2 降级为规则引擎并在响应中标注 `degraded`** |
| `MODEL_NAME` | 否 | `deepseek-chat` | 仅用于写入版本快照与运行日志的 `model` 字段；大模型客户端实际固定使用 `deepseek-chat` |
| `ENABLE_LLM_F1` | 否 | `0` | 设为 `1` 时，本地知识库未收录的概念会额外调用大模型补一段解释，该段被明确标注「未经核验」。默认关闭，纯本地运行不产生编造引用 |
| `TEACHER_ACCOUNTS` | 否 | 自动生成 | 教师账号，JSON 格式，例如 `{"teacher1":"你的口令"}` |
| `ADMIN_ACCOUNTS` | 否 | 自动生成 | 管理员账号，JSON 格式，例如 `{"admin":"你的管理员口令"}` |

`.env` 已被 `.gitignore` 忽略，**切勿提交到仓库**。

**账号配置的准确行为**：教师与管理员凭据只从环境变量读取，不写死在代码中。

- 变量已配置且为合法 JSON 时，系统使用其中定义的账号与口令。
- 变量未配置或为空时，系统为默认账号 `teacher`（教师）或 `admin`（管理员）**生成一次性随机口令**，并在启动日志中以 **WARNING** 级别打印一次：

```
[AUTH] 未配置 TEACHER_ACCOUNTS，已为账号 'teacher' 生成一次性随机口令：xxxxxxxxx  （请在 .env 中配置 TEACHER_ACCOUNTS 以获得固定口令）
```

- 该随机口令**每次重启都会变化**，仅适合临时试跑；需要固定口令请在 `.env` 中配置对应变量。
- 变量内容不是合法 JSON 时，系统打印 ERROR 日志并忽略该变量，随后按「未配置」处理并生成随机口令。

## 三、启动方法

### 3.1 启动服务

在项目根目录执行：

```bash
uvicorn main:app --reload --port 8121
```

也可直接运行入口脚本（等价，内部固定使用 8121 端口）：`python main.py`

### 3.2 访问地址

| 页面 | 地址 | 说明 |
|------|------|------|
| 学生工作台 | http://localhost:8121/ | 三个流程的主界面 |
| 教师看板 | http://localhost:8121/teacher | 需要教师或管理员账号登录 |
| 接口文档 | http://localhost:8121/docs | FastAPI 自动生成的 Swagger 文档 |

> **端口提示**：本版本启动命令使用 **8121** 端口。仓库根目录 README 中的示例为 8000，二者只是端口不同，按实际启动端口访问即可。使用自测试脚本时，必须让 `--base` 与实际端口一致（见第九节）。

### 3.3 关于 `/admin` 路径

访问 http://localhost:8121/admin 会返回 **HTTP 501**：

```json
{"detail": "管理员控制台页面（frontend/admin.html）尚未实现。",
 "available_api": ["/api/admin/global-dashboard", "/api/admin/users", "/api/admin/users/action"],
 "teacher_console": "/teacher"}
```

这是**如实说明而非故障**：管理接口（`/api/admin/*`）功能正常可用，只是独立的图形化管理员控制台页面尚未实现，系统不会静默回退到教师页面让人误以为存在管理员控制台。管理员日常操作请直接调用上述接口（见 4.4 节）。

## 四、账号与权限说明

| 角色 | 登录方式 | 口令来源 | 主要权限 |
|------|----------|----------|----------|
| 学生 | `POST /api/student/login` 或 `POST /api/session/start` | 首次登录时自动创建 | 使用 F1/F2/F3、上传文件、证据标注、评分、登记人工干预、删除自己的项目 |
| 教师 | `POST /api/teacher/login` | `TEACHER_ACCOUNTS` 环境变量 | 学生全部权限，另加班级看板、学生报告、教学干预、评分复核 |
| 管理员 | `POST /api/teacher/login`（同一入口） | `ADMIN_ACCOUNTS` 环境变量 | 教师全部权限，另加全局大盘、用户列表、角色变更 |

**学生**：在首页填写「你的名字或学号」与「访问密码」即可进入工作台。**首次登录即自动创建账号**，无需预先注册；再次登录须使用相同口令，否则返回 401「密码错误，请重试或更换学号」。学号不能为空且不超过 50 个字符。学生只能删除属于自己的项目，删除他人项目返回 403。

**教师**：在 `/teacher` 页面登录，或直接调用接口：

```bash
curl -X POST http://127.0.0.1:8121/api/teacher/login \
  -H "Content-Type: application/json" \
  -d '{"username":"teacher1","password":"你的口令"}'
# 返回：{"token":"token-teacher1","username":"teacher1","role":"teacher"}
```

后续教师接口需在请求头携带 token：`Authorization: token-teacher1`

教师接口：`GET /api/teacher/dashboard`（班级看板：有效项目数、高风险项目、规则触发排行榜、教学建议）、`GET /api/teacher/student/{session_id}/report`（学生能力评估报告）、`GET /api/teacher/student/{session_id}/grading_report`（批改评价报告）、`POST /api/teacher/intervene`（注入干预策略，下次学生对话时自动生效）、`POST /api/teacher/review-score`（复核并覆盖某条 R1—R9 评分，0—5 分，必须填写复核理由）、`DELETE /api/session/{session_id}`（删除会话）。

**角色校验规则**：未携带或格式错误的 token 返回 401「未授权，请先登录」；教师接口要求角色为 `teacher` 或 `admin`，管理员接口要求角色为 `admin`，否则返回 403「权限不足」。学生会话接口（`/api/chat` 等）以 `session_id` 与会话内记录的 `student_id` 作为归属依据，不需要 token。

**管理员**：使用与教师相同的登录入口，角色由 `ADMIN_ACCOUNTS` 决定。

```bash
# 全局大盘：项目总数、有效会话数、规则触发频率、Top3 业务漏洞、高风险数、教学建议
curl http://127.0.0.1:8121/api/admin/global-dashboard -H "Authorization: token-admin"
# 用户列表：返回教师与管理员账号名
curl http://127.0.0.1:8121/api/admin/users -H "Authorization: token-admin"
# 变更角色
curl -X POST http://127.0.0.1:8121/api/admin/users/action \
  -H "Authorization: token-admin" -H "Content-Type: application/json" \
  -d '{"target_username":"teacher1","action":"change_role","new_role":"admin"}'
```

> 当前 `action` 仅支持 `change_role`，其他取值返回 400「不支持的操作」。

## 五、三个流程的使用说明

三个流程可在学生工作台顶部的「项目指导 / 理论学习 / 评审反馈」标签间切换。**F1 与 F3 可不创建项目直接运行；F2 需要先创建会话。**

### 5.1 F2 项目指导（主流程，建议先跑）

**入口**：工作台默认标签「项目指导」，或 `POST /api/chat`；首次进入时系统自动调用 `POST /api/session/start` 创建会话。

输入字段：`session_id`（必填，必须已存在，否则返回 404「会话不存在，请重新开始」）、`message`（必填，非空且不超过 3000 字，超长返回 400「消息过长，请控制在3000字以内」）、`agent_mode`（可选，默认 `coach`，前端固定传 `coach`）。

首轮建议按欢迎语提示说清三件事：**谁**遇到了什么问题、他们现在如何解决、你准备改变什么结果。

响应字段：`coach_response`（教练回复）、`next_task`（唯一的下一步任务）、`thought_process`（图谱推理过程）、`detected_fallacies`（本轮触发的逻辑缺口，含 `rule_id`、`name`、`description`）、`capability_scores`（五维能力得分 0—10：痛点发现、方案策划、商业建模、资源杠杆、路演表达）、`current_phase`（`value_probe` 价值探测 / `pressure_test` 压力测试 / `landing_check` 落地校验）、`round_count`、`hypergraph_summary`、`degraded` / `degraded_reason`、`run_id`。

**什么情况算完成一轮**：一次成功的 `/api/chat` 调用即完成一轮，`round_count` 加一。推进节奏为：价值探测（谁有痛点、多痛、为什么你能解决）到压力测试（逐笔核算成本与收入）再到落地校验（团队能力与执行路径）。判断一轮质量的标准是：是否拿到明确的 `next_task`，且 `detected_fallacies` 中的缺口是否比上一轮减少。

**文件输入**：切到「项目指导」标签后点击「＋ 附件」上传材料，系统先解析文本再交给同一流程审计（见第七节）。

### 5.2 F1 理论学习

**入口**：工作台顶部「理论学习」标签，或 `POST /api/learn`。**无需创建会话，可独立运行。**

| 输入字段 | 必填 | 说明 |
|----------|------|------|
| `question` | 是 | 学习问题或概念名；全为空白字符时返回 400「请先输入一个学习问题」 |
| `test_id` | 否 | 默认 `manual`；自测试时填用例编号，写入运行日志 |

响应字段：`title`、`explanation`（概念解释）、`how_to_judge`（判断方法）、`common_pitfalls`（常见误区）、`positive_example` / `negative_example`（正反例）、`understanding_checks`（3 个理解检查问题）、`knowledge_base_hit`（是否命中本地知识库，为 `false` 时前端提示「本地知识库未收录该概念，以上仅为通用拆解路径」）、`source_note`（来源状态声明，本地词条一律为「本词条为课程自编的概念解释，未引用外部文献」）、`llm_enhanced` / `llm_supplement` / `llm_unverified_note`（仅在 `ENABLE_LLM_F1=1` 且未命中知识库时出现）、`run_id`。

本地知识库当前收录 13 个词条：问题—解决方案匹配、证据边界 F/I/H/S、价值主张、最小可行产品 MVP、市场规模测算 TAM/SAM/SOM、单位经济模型（CAC/LTV）、商业模式画布、竞争与替代方案分析、创新性与技术堆砌的区分、竞争壁垒与可持续性、挑战杯评审维度、关键假设与验证方法、波特五力模型。

**什么情况算完成**：拿到带 `title`、`explanation`、正反例、3 个理解检查问题与来源声明（`source_note`）的完整响应，即算完成一次学习。

### 5.3 F3 评审反馈

**入口**：工作台顶部「评审反馈」标签，或 `POST /api/review`。**无需创建会话，可独立运行。**

| 输入字段 | 必填 | 限制 |
|----------|------|------|
| `project_text` | 是 | 去除首尾空白后**至少 20 个字符**，否则返回 400「评审至少需要20个字符的项目材料」 |
| `rubric` | 否 | 默认「创业项目基础评审」 |
| `test_id` | 否 | 默认 `manual` |

输入应只包含项目内容本身。系统会自动剔除「请给出评价」「按以下维度分析」这类**指令性语句**，避免把评审要求误当成项目自己写了证据缺口。

响应字段：`overall_score`（总分 0—100）、`overall_5`（五维折算分 0—5）、`quality_level`（质量等级 0—4：不可用 / 严重缺陷 / 基本可用 / 良好 / 可靠，含锚点描述）、`dimensions`（五维逐项：维度名、满分、得分、状态（证据缺口 / 部分具备 / 已有线索）、已具备项、缺失项、封顶原因）、`evidence_gaps`、`evidence_distribution`（F/I/H/S 分布计数与整体提示）、`integrity_risks`（诚信风险提示）、`recommendations`（优先补强最弱维度）、`claim_labels`、`integrity_note`、`run_id`。

评分维度与权重：社会价值 20 分、实践/证据过程 20 分、创新意义 20 分、发展前景与可行性 25 分、团队协作与材料一致性 15 分。评分规则（确定性引擎，可复现、不随采样漂移）：

1. 每个维度按「必备证据命中比例」打分，确定性地最高给到该维度满分的 90%。
2. **证据门槛**：全篇未发现任何可定位来源时，任何维度得分不超过该维度满分的 **40%**，并在 `cap_reason` 中说明。
3. **技术堆砌封顶**：创新点若只落在「使用 AI / 大数据 / 区块链」等技术采用上而未说明新的作用机制，创新意义维度不超过该维度满分的 30%。

**什么情况算完成**：拿到含五维得分表、`evidence_gaps`、`recommendations` 与 `run_id` 的完整响应即算完成一次评审。建议把 `run_id` 一并记入项目材料版本记录。

## 六、证据边界 F/I/H/S 说明

### 6.1 四类标签

| 标签 | 名称 | 含义 | 现在能否采用 |
|------|------|------|--------------|
| **F** | 事实 | 已有可定位来源或明确材料支持 | 是——仍需标注来源出处 |
| **I** | 推断 | 基于事实作出的解释，仍需验证 | 仅可作为待验证输入，不得作为结论依据 |
| **H** | 假设 | 尚未被材料或数据支持的判断 | 仅可作为待验证输入，不得作为结论依据 |
| **S** | 模拟 | 课程 / 教师 / Agent 设定的情境，不等于真实市场证据 | 不得作为证据；只能用于生成待验证假设 |

### 6.2 标注接口

```bash
curl -X POST http://127.0.0.1:8121/api/evidence/classify \
  -H "Content-Type: application/json" \
  -d '{"text":"我们的目标是服务全国2000万大学生，预计第一年可覆盖10%的市场。"}'
```

输入为空返回 400「请输入需要标注的材料」。返回结构：

```json
{"claims": [{"claim": "陈述原文", "label": "H",
  "label_name": "假设：尚未被材料或数据支持的判断",
  "can_use_now": "仅可作为待验证输入，不得作为结论依据",
  "reason": "判定理由", "verification_step": "下一步核验动作"}],
 "run_id": "run_xxxxxxxxxxxx", "note": "自动分类仅作初筛，最终标注由项目成员负责。"}
```

### 6.3 判定顺序与使用注意

系统按以下顺序做**保守判定**（先排除「不能被当作事实」的情形，最后才考虑 F）：

1. **模拟 S**：出现「模拟」「教师提供」「案例包」「Agent生成」「角色扮演」「推演」「沙盘」等情境标记。
2. **无来源数字 → H**：包含具体数字（如「80%」「2000万人」「500万元」）但没有可定位来源的，一律不判为事实。
3. **推断 I**：出现「因此」「所以」「说明」「意味着」「推测」等推断连接词。
4. **假设 H**：出现「假设」「预计」「计划」「可能」「目标」「估计」等未验证判断标记。
5. **事实 F**：必须命中来源标记（「来源」「出处」「根据《」、统计公报、年鉴、论文、期刊、政府机构名、URL 等）。
6. **兜底 → I**：以上都不满足时，按保守口径降级为待核验陈述，**不给 F**。

使用注意：

- **否定感知**：「无来源」「没有调研」「缺乏数据」不会被当作存在证据（在关键词前后 8 个字符窗口内识别否定前缀）。
- **一条材料最多拆成 30 条陈述**进行标注，超长材料请分段提交。
- **来源标记不等于内容真实**：命中来源标记只说明文本中出现了来源线索，不代表系统核实过该来源。
- **自动标注只是初筛**，最终标注与责任由项目成员承担；无法核实的数字不得进入最终结论。

## 七、文件上传：格式与限制

文件上传**仅用于 F2 项目指导流程**。切换到 F1/F3 时「＋ 附件」按钮自动禁用；若切换前已选中文件，系统会清空该文件，避免 F2 形状的响应被渲染到评审界面。

| 项目 | 规定 |
|------|------|
| 允许的扩展名 | `.pdf`、`.docx`、`.doc`、`.txt`（其他扩展名返回 400「仅支持 PDF、DOCX、DOC 或 TXT 文件」） |
| 文件大小 | 不超过 10 MB，超出返回 413「文件不能超过 10MB」 |
| 文本提取失败 | 返回 422「无法提取文件文本，请检查文件是否为空或为扫描图片」 |
| 送入分析的长度 | 提取文本截断至 15000 字符 |

调用示例：

```bash
curl -X POST http://127.0.0.1:8121/api/upload \
  -F "session_id=你的session_id" \
  -F "file=@商业计划书.pdf" \
  -F "message=请重点审计第三章的市场规模测算"
```

`session_id` 必填且必须已存在；`message` 为可选补充说明，缺省时按「请审计这份项目材料，指出最关键的证据缺口」处理。响应包含 `filename`、`coach_response`、`next_task`、`detected_fallacies`、`capability_scores`、`current_phase`、`round_count`、`degraded`、`run_id`。

解析行为：

- 未配置 API Key 时，直接返回提取文本的前 15000 字符，不调用大模型。
- 已配置 API Key 时，调用大模型把材料提取为结构化商业要素（节点 / 二元边 / 超边）并交给项目指导流程审计；调用失败时降级返回原文本前 1500 字符。
- 送入分析的文本前会显式声明「请不要把其中未标注的数字自动视为事实」。
- 扫描版 PDF（图片型）不含文本层，会返回 422，需先做 OCR 转换。

## 八、常见问题与故障排查

### 8.1 API Key 未配置

**现象**：F2 能正常返回内容，但响应中 `degraded` 为 `true`，`degraded_reason` 为「LLM 调用失败」或「Critic 阶段 LLM 不可用，已改用确定性规则引擎完成审计」。

**判断方法**：

```bash
curl http://127.0.0.1:8121/api/version
```

返回中 `llm_configured` 为 `false`，即表示未配置 Key（或 Key 仍为模板值 `your_deepseek_api_key_here`）。

**处理**：在 `.env` 中填写有效的 `DEEPSEEK_API_KEY` 后重启服务。**这不是故障**——F1/F3 仍可完整使用，F2 也会以本地规则引擎给出完整结构的回复。

### 8.2 余额不足或服务不可用导致降级

**现象**：已配置 Key，但 F2 每轮都返回 `degraded: true`。

**原因**：`degraded` 的判定依据是**运行时异常**，余额不足、网络超时、服务端错误都会触发降级。

**排查步骤**：

1. 查看服务端控制台日志，会有形如 `[COACH] LLM unavailable, using local response: ...` 的 WARNING 行，其中包含异常类型。
2. 用 `GET /api/runs/{run_id}` 查看该次运行记录，`steps` 中会有一条 `degrade` 步骤，`error_type` / `error_detail` 字段记录了异常信息。
3. 若为余额问题，请充值，或临时切换到纯本地模式继续教学演示（F1/F3 完全不受影响）。

### 8.3 端口被占用

**现象**：启动时报 `error while attempting to bind on address ('0.0.0.0', 8121)` 或 `[Errno 10048]`。

```bash
netstat -ano | findstr :8121    # Windows
lsof -i :8121                   # Linux / macOS
```

**处理**：终止占用进程，或换端口启动（换端口后访问地址与测试 `--base` 需同步修改）：`uvicorn main:app --reload --port 8122`

### 8.4 文件解析失败

- **400 仅支持 PDF、DOCX、DOC 或 TXT 文件**：扩展名不在白名单内，请转换格式后重试。
- **413 文件不能超过 10MB**：压缩或拆分文件。
- **422 无法提取文件文本，请检查文件是否为空或为扫描图片**：文件为空、扫描版 PDF 无文本层，或旧版二进制 `.doc` 无法解析。建议另存为 `.docx` 或 `.pdf` 后重试。

### 8.5 如何查看运行日志与 run_id

每一次 F1/F2/F3、证据标注、评分调用都会生成唯一的 `run_id`：F1/F3 与证据标注的 `run_id` 直接在响应体中返回；F2 与评分接口同样返回 `run_id` 字段。学生工作台的 F1/F3 回复末尾会显示「运行编号」。

```bash
curl "http://127.0.0.1:8121/api/runs?limit=50"        # 最近 50 条（limit 取值 1—500）
curl "http://127.0.0.1:8121/api/runs?flow=F2&limit=20" # 只看 F2 流程
curl http://127.0.0.1:8121/api/runs/run_xxxxxxxxxxxx   # 单次运行完整记录
```

`GET /api/runs` 返回摘要字段：`run_id`、`flow`、`test_id`、`status`、`degraded`、`started_at`、`duration_ms`、`agent_version`、`git_commit`、`human_interventions`。

`GET /api/runs/{run_id}` 返回完整记录，含 `steps`（关键节点与状态）、`degraded_reason`、`error_type`、`error_detail`、`retry_count`、`human_interventions`。**记录不存在时返回 404**，请确认 `run_id` 抄写正确。

运行记录以 JSON Lines 格式落盘在 `logs/runs.jsonl`，可直接查看：`tail -n 20 logs/runs.jsonl`

日志写盘前会脱敏：API Key、`Authorization` 头、`token-` 前缀令牌、中国大陆手机号都会替换为掩码，自由文本截断至 300 字符。**日志不会记录 API Key。**

### 8.6 运行状态 `degraded` 的含义

运行状态有三种：`success`（正常完成）、`degraded`（任务完成但发生降级，例如改用本地规则引擎）、`failed`（未完成，`error_type` / `error_detail` 记录原因）。失败的运行记录同样全部保留、不会被删除或改写为成功，便于审计。

### 8.7 人工干预记录怎么填

凡是改写 Agent 输出、手工补齐遗漏模块、替换错误引用、修改测试输入、重跑失败任务，都应登记：

```bash
curl -X POST http://127.0.0.1:8121/api/intervention \
  -H "Content-Type: application/json" \
  -d '{"session_id":"你的session_id","kind":"修改","detail":"人工改写了 F3 的修改建议第 2 条","run_id":"run_xxxxxxxxxxxx"}'
```

`kind` 必须是以下六种之一：**补充、修改、确认、绕过、重跑、纠错**，否则返回 400。`run_id` 可选，填写后可用于回溯到具体某次运行。**人工成果不得计为 Agent 能力。**

### 8.8 会话不存在或数据丢失

- 所有接口在 `session_id` 无效时返回 404「会话不存在，请重新开始」。
- 会话与用户数据分别持久化在 `storage/sessions.json` 与 `storage/users.json`，服务重启后仍可加载；文件损坏或为空时以空存储启动，需重新创建项目。

## 九、如何运行自测试

自测试脚本 `tests/run_tests.py` 覆盖课程统一测试集 U1—U6 与组内回归测试。**前置条件：先启动服务**。

```bash
uvicorn main:app --reload --port 8121     # 先启动服务

python tests/run_tests.py                                        # 默认打到 8000
python tests/run_tests.py --base http://127.0.0.1:8121           # 指定本项目实际端口（推荐）
python tests/run_tests.py --base http://127.0.0.1:8121 --label V2-修订后   # 带标签，便于 V1/V2 对比
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--base` | `http://127.0.0.1:8000` | 服务地址，必须与实际启动端口一致 |
| `--label` | `V2` | 报告标签，用于 V1/V2 对比 |
| `--suite` | `both` | `unified` = 统一测试集 U1—U6；`custom` = 组内回归测试；`both` = 全部 |

用例覆盖：**U1** F1 理论学习；**U2** 证据标注（F/I/H/S 分类）；**U3** F2 项目指导首轮；**U4** F2，依赖 U3 建立的会话上下文，**在同一会话内按顺序执行**；**U5** F3 评审反馈；**U6** 异常处理，逐项触发六类异常并检查是否如实报错（不支持的文件类型、文件无法解析、会话不存在、输入超长、评审输入过短、学习问题为空）。

**输出位置**：报告写入 `tests/reports/` 目录，文件名带标签与时间戳。

- `tests/reports/<label>_<时间戳>.json`：机器可读的完整结果（含原始响应）。
- `tests/reports/<label>_<时间戳>.md`：人类可读的自测试报告。

Markdown 报告包含：运行环境（Agent 版本、提示词版本、知识库版本、git 提交号、工作区是否有未提交改动、模型、服务地址）、结果汇总、逐项校验结果与证据，以及**未通过项清单**。

退出码：`0` 全部通过；`1` 存在未通过项；`2` 无法连接服务（会打印 `!! 无法连接 <base>`）。

> 测试报告**全部保留**，包括失败项，不做任何过滤——失败样本不被删除是证据完整性的要求。若报告中 `git_dirty` 为 `true`，说明工作区有未提交改动，此时 `git_commit` 不能单独作为版本凭证，需同时留存目录快照。

## 十、已知限制清单

以下限制均基于当前代码实现，如实列出以便使用者判断适用范围。

1. **`/admin` 返回 501**：`frontend/admin.html` 不存在，独立管理员控制台页面尚未实现。`/api/admin/*` 接口功能正常，管理员需通过接口或 Swagger 文档操作。
2. **管理员角色变更不持久化**：`/api/admin/users/action` 直接修改内存中的账号表，未写入磁盘，服务重启后变更丢失。
3. **该接口只实现 `change_role`**：传 `add` 或 `remove` 返回 400「不支持的操作」，即不支持通过接口新增或删除教师/管理员账号（需改 `.env` 后重启）。
4. **学生账号无鉴权校验**：首次登录自动创建账号，`/api/chat` 等接口只以 `session_id` 为凭据，不校验 token。
5. **学生口令以明文保存**在 `storage/users.json` 中，仅适用于课程本地演示环境，请勿使用常用真实密码。
6. **教师/管理员口令为明文比较**，token 形如 `token-<用户名>` 且不做过期与签名校验，仅适合教学内网环境。
7. **未配置账号环境变量时生成的一次性随机口令每次重启都会变化**，且只打印一次，请及时保存或改用固定配置。
8. **跨域策略为允许所有来源**（`allow_origins=["*"]`），不适用于公网部署。
9. **F2 单条消息上限 3000 字**，超长直接返回 400。
10. **F1 知识库仅收录 13 个概念**，未命中时只输出通用拆解路径，不提供该概念的定义。
11. **F3 评审至少 20 字符**，一次评审最多解析 30 条陈述用于标注，超长材料需分段提交。
12. **`/api/score` 依赖已有会话**：需要 `session_id`，会话不存在返回 404；该节点独立于 F2 的逐轮对话，不会每轮自动运行。
13. **R1—R9 总分为 9 项得分的简单平均（0—5 分制）**，`RUBRIC_ITEMS` 中定义的 `weight` 字段目前未参与总分加权计算，各维度权重合计为 0.90。
14. **大模型调用为串行非流式**，长文本场景响应较慢；自测试客户端超时设为 180 秒。
15. **`.doc` 旧版二进制格式实际无法解析**：该扩展名虽在白名单内，但解析走 `python-docx`（仅支持 OOXML），会返回 422。请另存为 `.docx` 后上传。
16. **不支持扫描版 PDF**：无 OCR 能力，无文本层时返回 422。
17. **文本截断**：文件提取文本送入分析时截断至 15000 字符；大模型摘要失败时降级为前 1500 字符。
18. **附件仅用于 F2**，F1/F3 没有文件入口。
19. **来源标记不等于内容真实**：F3 的来源识别只是文本线索匹配，系统不联网核实，评审结论需人工复核。
20. **F3 代码实现的门槛与响应文案存在不一致**：`workflows.py` 中实际的证据门槛为「全篇无可定位来源时不超过维度满分的 **40%**」，而响应里 `scoring_note` 字段的说明文字写的是 50%。**以代码实现的 40% 为准**，该文案待修正。
21. **`MODEL_NAME` 环境变量只影响版本快照与运行日志中记录的模型名**，实际调用大模型的客户端固定使用 `deepseek-chat`。
22. **F1 的大模型增强默认关闭**（`ENABLE_LLM_F1=0`），开启后补充内容一律标注「未经核验」，不得直接写入正式材料。
23. **确定性引擎的满分上限**：F3 单维度确定性最高只给该维度满分的 90%，剩余空间留给大模型增强层与人工判断，避免出现「机器算满分」的结论。
24. **单机文件存储**：会话、用户与运行日志均为本地 JSON / JSONL 文件，无数据库、无并发写保护，不适合多实例部署。
25. **会话数据在启动时一次性载入内存**，运行期间以内存为准并整体覆写落盘；手工编辑 `storage/sessions.json` 需重启服务生效。
26. **运行日志只增不减**：`logs/runs.jsonl` 不会自动清理，长期使用需手工归档。
