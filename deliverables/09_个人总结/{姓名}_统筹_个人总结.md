## 二、我在这次课程里最重要的收获

这次课程让我最难忘记的一刻，是发现 Agent 会把一句完全没有来源的话标成「事实」。

测试时我输入「学校支持建立教材交易平台」——这句话是我随手编的，没有任何依据。系统给出的标签是「事实：已有可定位来源或明确材料支持」，并且告诉学生「可以直接采用」。

那一刻我意识到两件事。第一，如果我不加核对就用这个输出，我会把一个凭空断言写进立项材料，而且它还带着系统的「事实」背书。第二，这个问题比「回答不准」严重得多——回答不准我能看出来，但一个看起来专业的错误标签，我可能直接就信了。

后来我们重建了分类器，把默认值从「事实」改成「待核验」。我也因此养成了一个习惯：任何进入材料的关键数字，我都会去追它的原始来源。

在收集证据的过程中，我还发现自己有一个倾向——**想让证据支持我的结论**。比如我一开始很希望找到「社区食堂浪费率高达 X%」这样的权威数据，找了几轮没找到。当时有点沮丧，甚至想过找个沾边的数字放上去。最后我没有这么做，而是如实写成：A 级来源只支撑人口规模和政策要求，「备餐浪费严重」这一判断目前只有 B 级支撑。

这句话写在文档里其实不太好看。但我现在觉得，把它写出来才是对的。

## 三、我遇到的最大困难与解决过程

**最大的困难是：权威来源支撑不了我最想要的结论。**

我一开始以为「老年助餐浪费严重」这个判断很好找证据。实际找下来发现，民政部的统计公报里有老年人口数、养老机构数、资金规模，但**没有单列全国助餐点数量，也没有浪费率**。真正说到浪费问题的，都是媒体报道转述的调研，属于 B 级。

我一度很纠结，甚至想过用「社区养老服务机构和设施 36.3 万个」当作助餐点数量来用——反正数字看着挺唬人。但这个数字是「社区养老服务机构**和设施**」总数，不等于助餐点，用了就是偷换口径。

最后我选择如实分层：A 级来源支撑什么就写什么，B 级来源标注「据报道」，并把这个缺口作为下一阶段的首要验证项写进计划。

**第二个困难是不知道什么算「足够好的证据」。** 我一开始收集了十几条资料，感觉很多，但整理成台账时才发现，一半以上是同一个来源的重复转述。后来我用 Agent 的 F3 评审流程对我的材料做了一次自评——它给我指出的第一条缺口就是「全篇没有可定位来源」，我才意识到我列的那些「某市数据显示」根本没有给出机构、标题和年份。

## 四、我如何使用 Agent，以及人工介入的地方

我用得最多的是 **F3 评审反馈**流程。我会把写完的章节粘进去，让它按社会价值、实践依据、创新意义、发展前景和团队条件五个维度挑问题。它指出过几个我自己没注意到的地方：

- 我的用户描述一开始写的是「社区老年人」，被判定用户过宽，这是我的实际问题
- 我在创新点里写了「利用大数据技术」，它提示去掉技术名词后创新点就没了

它也有明显的不足。**它给不出我不知道的东西**——它只能检查我写的内容有没有结构性问题，没法告诉我应该去找什么资料。而且因为我们的 API 余额不足，项目指导流程一直在降级模式跑，所以 F2 用得不多。

**人工纠正的地方**：F3 一开始给一个明显没证据的项目打了 87 分，我当时的第一反应是「这分数不对」，但说不出哪里不对。后来定位到是「无来源」三个字包含了「来源」，被系统当成了存在证据。这个 bug 是我发现现象、由负责开发的同学定位根因的。
